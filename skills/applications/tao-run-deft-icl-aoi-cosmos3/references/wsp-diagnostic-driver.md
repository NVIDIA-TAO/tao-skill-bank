# One-shot text diagnostic driver

`scripts/wsp_diagnostic.py prepare` seals a manifest without launching a process,
reading credentials or accessing model/data payloads. The separately approved
`run` verb uses the reviewed sandbox, provider route, capture, invocation and
collector primitives. It never invokes scientific `run` or creates that result
directory. Prepare the scientific proposal with the driver included in its code
hashes; all scientific data/profile/budgets remain frozen.

```bash
python scripts/wsp_diagnostic.py prepare \
  --scientific-preflight /private/preparation/preflight.proposed.driver.json \
  --output /private/preparation/diagnostic.manifest.json \
  --run-dir /private/runs/wsp-token-diagnostic-01 \
  --codex-binary /approved/codex \
  --auth-file /approved/private/auth.json
```

The sealed manifest binds code/binaries/helpers/image/model/effort/provider route,
the exact invocation template and prompt, deterministic fixture bytes, scientific
identity, explicit diagnostic differences and limits. Only the actual minted job
ID replaces the template placeholder. The host writes it before container launch.
The manifest is read-only and hash-bound; an existing attempt directory is never
overwritten, resumed or retried. A failed setup also consumes this one directory.

`run` requires a separate coordinator-written approval containing
`diagnostic_manifest_sha256`, `approved_for_live_text_diagnostic: true`,
`approved_by` and `approved_at`. A scientific or preparation approval does not
authorize it. No approval is generated by the driver.

```bash
python scripts/wsp_diagnostic.py run \
  --manifest /private/preparation/diagnostic.manifest.json \
  --approval /private/review/diagnostic.approval.json
```

The native threshold is50,000 raw input+output, cache included once. The host
observes180seconds (starting before the access probe),100,000 raw emergency
tokens, bounded streams and retained bytes. It requests only its own child's
stop, harvests final bounded tmpfs content before releasing the wrapper, then
stops its own jobs/services on every path. Polling, stop grace and in-flight API
usage can overshoot an observed guard; all actual usage/exit/elapsed cleanup and
partial evidence remain recorded. An outer stop is never native-budget proof.

A host-owned Unix endpoint admits at most10 requests and saves the count before
responding; malformed requests also spend admission. Each response is less than
512bytes of deterministic synthetic text. The editor has no WSP operations,
model context, real data, images, labels, weights or GPU. Its prompt asks for
sequential fixture requests, without prescribing model usage or native events.
The final count and owned-job terminal states must agree before proof proposal.

The2CPU/4GiB/noGPU sandbox and Codex flags are reused. Native log rotation is
explicitly reduced to16MiB for each of the two owned access-probe/editor jobs.
The128MiB retention envelope reserves32MiB for those native logs and4MiB framing
headroom, leaving92MiB for the host attempt tree, including2MiB final status
reserve. Host log/archives are streamed with limits; excess bytes are truncated,
disclosed and classified inconclusive. Archives are never extracted. The shared
scientific sandbox retains its original default log bound.

The default Docker terminal-status helper duplicates unbounded logs, so this
driver uses its own bounded status adapter over the same record/native lifecycle.
It inspects/cancels only IDs minted by this attempt. No packages/images are pulled;
no credentials are printed, exported or hashed. Existing auth is a private
read-only mount through the same allowlisted provider route.

Only completely retained native evidence passing `response_completion`, with
multiple genuine cumulative snapshots, cached input and native budget exhaustion
at the actual threshold, produces `live_proof.proposed.json`. The outcome is
`NATIVE_STOP_OBSERVED_REVIEW_REQUIRED`, never automatic scientific authorization.
Early voluntary completion, missing cache/usage, additional completed responses,
API errors, limits or cleanup failure produce `INCONCLUSIVE` with exact reasons.
The later reviewer supplies proof approval. Native events do not directly expose
per-request admission; that observability limit remains explicit.

CPU tests use fake backends, synthetic native fixtures and tiny ordinary Python
subprocesses. They cover resource guards, host-counter exhaustion, bounded
truncation, exceptions/cleanup, no resume and collector/proof compatibility.
They do not launch Codex/API traffic or prove live stopping semantics.
