# cosmos-framework dependency set for a NATIVE Windows host (no WSL, no container).
#
# WHY THIS FILE EXISTS
# --------------------
# These are the exact versions pip resolved to in the verified Windows image and
# in the verified host venv. They are pinned, not floated, because three of them
# are load-bearing in a way that is invisible until a run dies:
#
#   torch==2.13.0+cu130      the ONLY line shipping cuDNN 9.20. cosmos-framework
#                            gates its cuDNN attention backend on
#                            CUDNN_MIN_BACKEND_VERSION = 92000; below that the
#                            backend silently disables itself and falls back to
#                            NATTEN, which has no Windows build at all.
#   torchcodec==0.14.0+cu130 links FFmpeg 7.x (avformat-61).
#   torchvision==0.28.0+cu130
#
# The three +cu130 wheels are not on PyPI. Install with:
#
#   pip install -r requirements-cosmos3-win.txt \
#       --extra-index-url https://download.pytorch.org/whl/cu130
#
# NOTE ON pytest
# --------------
# pytest is listed here as a RUNTIME dependency of TRAINING, not as a test-only
# extra. It is not optional and it is not a mistake. cosmos-framework's
# configs/base/reasoner/config.py recursively imports every module in its
# experiment package at config-load time, and one of those modules
# (configs/base/reasoner/experiment/tao_video_sft_test.py) does `import pytest`
# at module scope. Without it, `cosmos-framework-train` dies before it reads a
# single byte of the recipe:
#
#   ModuleNotFoundError: No module named 'pytest'
#
# The verified container image carries pytest==9.1.1 for exactly this reason.
# Removing it from this list breaks training, not tests.
